## 1. 产品概述

FormulaBridge 是一款面向 Microsoft Word 的本地优先 LaTeX 公式编辑器。它保留高频 LaTeX 用户熟悉的源码输入、编译预览、行内/独立/编号公式、章节编号、交叉引用和快捷编辑逻辑，同时采用适合现代 Word 的文档格式与插件架构。

FormulaBridge 是独立开发的新产品，不复制或分发 Aurora 的代码、二进制文件、图标、帮助文档、激活机制或安装包资源。产品可以兼容其操作习惯和依法取得的旧文档，但使用新的名称、视觉资产、代码和数据格式。

## 2. 产品愿景与价值

FormulaBridge 要解决的核心问题是：让用户在 Word 中获得接近专业 LaTeX 编辑器的输入能力，同时避免旧式 OLE 公式在新版 Windows、64 位 Word、打印、PDF 导出和插件缺失时出现兼容性问题。

产品价值包括：

- 保留 LaTeX 源码输入效率，而不是强迫用户逐个点击数学符号。
- 常见公式保存为 Word 原生 OMML，可以搜索、复制、辅助阅读和继续编辑。
- 复杂公式使用本地 TeX 高保真渲染，不依赖远程服务器。
- 文档离开本机或卸载 FormulaBridge 后，公式仍可显示、打印和导出。
- 支持编号、章节和交叉引用等完整论文写作工作流。
- 可以在多个 TeX 发行版和引擎之间明确选择，避免隐式环境变化。
- 提供非破坏性的旧 Aurora 文档迁移能力。

## 3. 设计原则

1. **文档优先**：公式必须随 Word 文档自包含，不依赖外部图片路径或云端资源。
2. **OMML 优先**：能够正确表示的公式优先写入 Word 原生 OMML。
3. **TeX 保真回退**：超出 OMML 支持范围的公式通过本地 TeX 渲染为自包含 SVG，并嵌入 PNG fallback。
4. **源码不丢失**：每个公式保存 LaTeX 源码、渲染选项和稳定标识。
5. **离线优先**：编辑、编译、预览、插入和迁移不要求联网。
6. **显式环境**：文档使用哪个 TeX 配置必须可见、可选择、可诊断。
7. **失败不改文档**：解析或编译失败时，不插入半成品，也不覆盖原公式。
8. **进程隔离**：Word 集成、编辑器和 TeX 编译相互隔离，渲染崩溃不得拖垮 Word。
9. **独立实现**：延续操作逻辑但不复制受保护的具体表达和品牌资产。

## 4. 目标用户与使用场景

### 4.1 目标用户

- 使用 Word 撰写论文、教材、报告和技术文档的高校师生。
- 熟悉 LaTeX、但交付格式必须是 Word 的科研和工程人员。
- 需要公式编号、章节编号和交叉引用的长文档用户。
- 需要使用 `amsmath`、`mathtools`、`physics`、`siunitx`、`mhchem` 等宏包的专业用户。
- 持有旧 Aurora 文档并希望迁移到新版 Word 的用户。
- 对文档离线性、隐私和可长期打开有要求的企业或研究机构。

### 4.2 核心场景

- 在光标处插入行内、独立或编号公式。
- 选中或双击现有公式后重新编辑 LaTeX 源码。
- 使用本地宏包和自定义命令生成复杂公式。
- 为不同项目选择不同版本的 TeX Live、MiKTeX 或自定义 TeX 环境。
- 在文档中批量更新公式样式、编号和渲染结果。
- 插入和维护跨章节公式引用。
- 将旧 Aurora OLE 公式迁移为 FormulaBridge 的 OMML 或 SVG 公式。

## 5. 支持范围

### 5.1 首发正式支持

- Windows 11 x64。
- Microsoft 365 Word 的受支持更新通道。
- Word / Office 2024 x64。
- `.docx`、`.docm`、`.dotx`、`.dotm`。
- TeX Live、MiKTeX 和用户指定的兼容本地 TeX 安装。

### 5.2 扩展支持

- 32 位 Microsoft 365 Word / Office 2024。
- Windows 11 ARM64。
- Word 2021 的尽力兼容。
- Word 网页版和 macOS 的有限 Office.js 体验。
- PowerPoint、Excel 和 Visio 公式插入。

### 5.3 首发不承诺

- 将 Word 2016、Office 2019 或 Windows 10 作为正式支持基线。
- 在未安装 FormulaBridge 时编辑 SVG 回退公式的 LaTeX 源码。
- 默认允许任意 LaTeX 源码启动外部程序或访问网络。
- 对没有源码、只有低清图片的旧公式保证自动恢复 LaTeX。

## 6. 产品界面与信息架构

### 6.1 安装与 Word 功能区

正式安装包完成以下操作：

- 安装 FormulaBridge Word 集成组件和本地 RenderHost。
- 注册签名的 Word 插件和功能区命令。
- 不修改系统 `PATH`，不替换用户现有 TeX 配置。
- 安装完成后提示重新启动 Word。

重新启动 Word 后，用户应看到：

- “插入”选项卡中的 FormulaBridge 分组。
- 独立的“FormulaBridge”选项卡。

主要功能区命令：

- 行内公式。
- 独立公式。
- 编号公式。
- 编辑当前公式。
- 上一个公式 / 下一个公式。
- 插入公式编号。
- 插入交叉引用。
- 更新全文编号。
- 从 TeX 粘贴。
- 批量属性。
- TeX 环境与 FormulaBridge 设置。

如果插件被 Word 信任中心、组策略或安全软件禁用，FormulaBridge 应提供可执行的诊断说明，而不是只显示笼统错误。

### 6.2 公式编辑界面

编辑器同时提供以下两种形态：

- Word 右侧停靠任务窗格，适合连续编辑。
- 可分离的浮动编辑窗口，适合接近传统桌面编辑器的工作流和多显示器使用。

编辑器布局包括：

- 顶部菜单和常用公式结构工具栏。
- LaTeX 源码编辑区，包括行号、语法高亮、括号匹配和光标位置。
- 实时预览区。
- 错误、警告和完整 TeX 日志面板。
- 当前公式类型、输出方式和 TeX 环境状态。
- “刷新”“插入”“更新”“取消”和“保存并关闭”操作。
- 公式属性、文档 preamble、宏包和环境设置入口。

### 6.3 基本交互

插入公式：

1. 用户在 Word 中选择行内、独立或编号公式。
2. FormulaBridge 打开编辑器并继承当前字号、颜色和上下文。
3. 用户输入 LaTeX，编辑器生成实时预览。
4. 用户确认后，FormulaBridge 将公式写入 Word。
5. 写入完成后，Word 的撤销操作可以一次撤销整个插入。

编辑公式：

1. 用户双击公式、选择公式后点击“编辑”，或使用快捷键。
2. FormulaBridge 读取公式 UUID、LaTeX 源码、环境和样式。
3. 用户修改并成功编译后，FormulaBridge 原位替换可见内容。
4. 编译失败或用户取消时，原公式保持不变。

## 7. 核心功能设计

### 7.1 公式类型

- **行内公式**：与正文同行，正确处理基线和行距。
- **独立公式**：单独成段并居中显示。
- **编号公式**：公式居中，编号按模板右对齐，并可被 Word 交叉引用。

公式可以在三种类型之间转换。转换操作必须保持 UUID、LaTeX 源码、标签和已有引用关系。

### 7.2 双渲染管线

FormulaBridge 使用两条互补管线。

#### 原生 OMML 管线

适用于分数、根式、上下标、矩阵、常用符号、运算符、函数、文本和常见数学结构。

特点：

- 输出为 Word 原生公式。
- 插件缺失时仍可编辑。
- 适合搜索、辅助技术和文档长期保存。
- 编译速度快，不需要启动 TeX 进程。

#### 本地 TeX 高保真管线

适用于复杂宏包、自定义宏、特殊字体、复杂对齐和 OMML 无法正确表达的结构。

推荐输出链：

```text
LaTeX / XeLaTeX / LuaLaTeX
    -> DVI 或 PDF
    -> dvisvgm 生成自包含 SVG
    -> dvipng 或等效工具生成 PNG fallback
    -> 嵌入 Word 文档
```

SVG 应尽量把字体转为路径，避免接收方必须安装相同字体。PNG 仅作为旧客户端或异常情况下的兼容预览。

用户可以显式选择“Word 原生”“本地 TeX”或“自动”。自动模式先尝试语义正确的 OMML；遇到不支持的构造时切换到本地 TeX，不得产生看似成功但数学含义错误的输出。

### 7.3 LaTeX 编辑能力

- 语法高亮和括号匹配。
- 常用命令、环境、宏包和自定义宏补全。
- 公式片段与用户模板。
- `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 和常见数学环境识别。
- `equation`、`align`、`gather`、`multline`、`split` 和矩阵环境。
- 中文文本和 Unicode 数学符号。
- 错误定位到源码行、列和相关命令。
- 查看简化错误和完整 TeX 日志。

### 7.4 宏包、preamble 与自定义命令

宏包配置分为四级：

1. 全局默认 preamble。
2. TeX 环境配置级 preamble。
3. 当前 Word 文档 preamble。
4. 单个公式附加设置。

优先级从全局到公式逐级覆盖。界面应支持：

- 编辑 `\usepackage` 和 `\newcommand`。
- 检测宏包是否安装。
- 显示缺失宏包及所属 TeX 环境。
- 保存命名 preamble 模板。
- 在插入前执行“测试编译”。
- 提示不同宏包或命令定义之间的冲突。

### 7.5 多 TeX 环境管理

FormulaBridge 自动检测并允许手动添加多个环境：

- 不同年份的 TeX Live。
- MiKTeX。
- 便携式 TeX 目录。
- 用户指定的自定义工具链。

每个环境以配置档案表示，包含：

- 配置名称和稳定 ID。
- 发行版和版本。
- `latex`、`pdflatex`、`xelatex`、`lualatex` 路径。
- `dvisvgm`、`dvipng` 等输出工具路径。
- TEXMF 和附加宏包目录。
- 默认引擎、preamble、超时和安全策略。
- 最近一次健康检查结果。

用户可以设置：

- 全局默认环境。
- 文档默认环境。
- 单个公式环境。
- 临时测试环境。

FormulaBridge 调用可执行文件的绝对路径，不依赖或修改系统 `PATH`。文档只保存环境 ID、发行版提示和所需能力，不保存必须完全一致的本机绝对路径。另一台电脑缺少对应环境时，必须要求用户映射兼容环境，不得静默换用其他引擎。

### 7.6 编号与交叉引用

- 连续编号和自定义起始值。
- 按 Word 标题级别生成章节号、节号和公式号。
- 手动章节/节分隔标记。
- 自定义括号、前缀、后缀、分隔符和数字格式。
- 插入、删除、复制或移动公式后自动重排。
- 每个编号公式拥有稳定标签，例如 `eq:maxwell`。
- 按标签、编号、章节或公式预览搜索引用目标。
- 使用 Word 字段和书签实现可更新引用。
- 检查断开引用、重复标签和孤立编号。
- 支持“更新当前章节”和“更新全文”。

复制到另一个文档时，应为冲突 UUID 和标签生成明确的解决方案，同时保持公式源码随对象移动。

### 7.7 批量操作

- 更新所选、当前章节或全文公式。
- 批量修改字号、颜色、背景、渲染方式和 TeX 环境。
- 批量验证宏包和编译结果。
- 查找和替换公式源码。
- 检查 Word 原生公式与保存的 LaTeX 源码是否发生分歧。
- 生成公式清单、错误报告和迁移报告。

### 7.8 导入、导出与剪贴板

- 从纯 LaTeX 文本粘贴并识别公式分隔符。
- 导入 LaTeX、OMML 和 Presentation MathML。
- 导出 LaTeX、OMML、MathML、SVG、PNG 和 PDF 片段。
- 复制公式时同时提供适合 Word、网页和纯文本的剪贴板格式。
- 任何格式转换发生语义或排版降级时必须提示用户。

### 7.9 旧 Aurora 文档迁移

迁移功能使用独立实现的扫描器识别旧 `Equation.Ribbit` OLE 对象，不注册或冒用 Aurora 的 CLSID、ProgID 或品牌。

迁移流程：

1. 扫描文档并生成旧公式清单。
2. 尝试提取 LaTeX 源码、公式类型、字号、渲染方式和编号信息。
3. 为每个公式预览建议的 OMML 或 SVG 输出。
4. 用户确认后保存为新文档，不覆盖原文件。
5. 生成成功、警告、失败和人工处理项的审计报告。

若旧公式没有可恢复源码，应保留原始可见内容，并允许用户选择 OCR、手工录入或保持原对象。迁移功能的正式发布以真实旧文档语料验证和法律审核为前提。

### 7.10 设置与诊断

设置中心包括：

- Word 集成和功能区状态。
- TeX 环境管理。
- 默认公式类型、渲染方式、字号和颜色。
- 宏包与 preamble 模板。
- 编号规则和引用格式。
- 快捷键。
- 缓存和临时文件策略。
- 日志级别、隐私和可选遥测。
- 更新通道和版本回滚。

“诊断”功能应生成不含公式源码的默认诊断包，并允许用户明确选择是否附加源码、文档片段或完整日志。

## 8. 技术架构

```text
Microsoft Word
  |-- x64 VSTO 主插件：Ribbon、Word 事件、内容插入、迁移入口
  |-- WebView2 编辑器：任务窗格、浮动窗口、源码、预览和设置
  |
  v
FormulaBridge Core
  |-- LaTeX parser / AST / diagnostics
  |-- OMML writer / HTML preview
  |-- Formula metadata / numbering / references
  |
  +--------------------+
  |                    |
  v                    v
OMML fast path     FormulaBridge.RenderHost.exe
                       |-- Engine profile manager
                       |-- TeX process sandbox
                       |-- latex / pdflatex / xelatex / lualatex
                       |-- dvisvgm / dvipng
                       v
                    SVG + PNG + log
```

### 8.1 组件职责

- **VSTO Word 插件**：作为 Windows 首发主集成层，处理 Ribbon、任务窗格、Word 事件和文档操作，但不在 Word 进程内执行 TeX 编译。
- **WebView2 编辑器**：承载 TypeScript 编辑界面，复用任务窗格与浮动窗口的源码、预览、错误和设置功能。
- **FormulaBridge Core**：负责语义解析、OMML、元数据、编号和一致性规则。
- **RenderHost**：独立的每用户进程，负责环境检测、受限进程启动、输出转换和日志。
- **迁移助手**：必要时使用独立 32 位进程读取旧 32 位 OLE 对象，并把结果交给现代核心。
- **Office.js 适配器**：作为后续 macOS、Word 网页版或轻量体验的可选入口，不是 Windows 首发主集成层。

WebView2 通过受控 Web Message 与 VSTO 宿主通信，VSTO 通过当前用户可访问的 Named Pipe 调用 RenderHost。正式版本不开放本地 HTTP 编译接口。接口必须限定调用来源、请求大小、并发和超时。

## 9. 文档与数据模型

每个公式拥有稳定 UUID，并保存以下逻辑记录：

```json
{
  "schemaVersion": 1,
  "id": "fb-...",
  "source": "\\frac{a}{b}",
  "mode": "inline",
  "outputKind": "omml",
  "engineProfileId": "texlive-2024-xelatex",
  "engineRequirement": {
    "engine": "xelatex",
    "packages": ["amsmath"]
  },
  "style": {
    "fontSizePt": 11,
    "color": "#000000"
  },
  "numbering": {
    "label": null,
    "formatProfileId": "default"
  },
  "sourceChecksum": "...",
  "visibleChecksum": "...",
  "createdAt": "...",
  "updatedAt": "..."
}
```

保存策略：

- 可见 OMML 或 SVG 位于内容控件中。
- 内容控件 tag 保存 FormulaBridge 标识和公式 UUID。
- 文档级设置保存索引、默认环境、preamble 和编号规则。
- 每个公式还应包含可随复制粘贴移动的对象级源码元数据。
- SVG 输出包含 PNG fallback，不使用外部链接。
- 文档打开时不自动重编译全部公式；只有源码、环境或渲染版本变化时才需要更新。

如果用户绕过 FormulaBridge 直接修改 OMML，FormulaBridge 通过校验值检测分歧，并提供“以 Word 内容为准”“以 LaTeX 源码为准”或“另存副本”选项。

## 10. 安全与隐私

### 10.1 TeX 安全

- 默认强制 `-no-shell-escape`。
- 每次编译使用独立随机临时目录。
- 不把 Word 文档目录设为 TeX 工作目录。
- 限制编译时间、内存、进程数、输出文件数量和大小。
- 限制可执行文件为所选环境配置中的明确路径。
- 宏包和命令采用风险分级；需要外部进程的功能默认禁用。
- 默认禁止公式通过 TeX 访问网络。
- 编译结束后清理临时文件，失败时只保留经用户授权的诊断信息。

### 10.2 本地接口安全

- RenderHost 只监听本机接口或 Named Pipe。
- 使用每用户会话令牌并校验调用来源。
- 不允许其他网页任意调用本地 TeX 编译能力。
- 对源码长度、请求频率和并发设置上限。

### 10.3 隐私

- 公式源码、文档内容和编译日志默认不离开本机。
- 遥测默认不包含公式源码、文件名、用户路径和文档内容。
- 远程渲染、云同步和问题诊断上传必须单独选择加入。

## 11. 安装、部署与更新

- 提供签名的 Windows 安装包。
- 支持当前用户安装和管理员集中部署。
- 明确检查 Word 位数、受支持版本、WebView2 和 VSTO 运行时。
- 安装 RenderHost、Word 桥接组件、Office.js 资源和卸载器。
- 不捆绑未经许可的 Aurora 文件、TeX 宏包或字体。
- TeX 可由用户自行安装，也可在许可证允许时提供独立可选组件。
- 支持静默安装、代理环境、更新通道和安全回滚。
- 卸载后不破坏已插入文档中的公式。

## 12. 非功能要求

### 12.1 性能

- 打开文档时不批量重编译现有公式。
- OMML 常用公式的预览应接近实时。
- 本地 TeX 冷启动允许显示进度，热路径应复用环境探测结果和安全缓存。
- 含 1000 个公式的文档应可正常打开、保存、滚动和执行批量检查。
- 批量任务可取消，并报告已经完成和未处理的项目。

### 12.2 稳定性

- RenderHost 崩溃不得导致 Word 退出。
- 所有文档写入操作应支持 Word 撤销。
- 更新公式前保留旧内容，成功后再原子替换。
- 损坏的元数据不得被空记录静默覆盖。
- 突然断电或 Word 异常退出后，可见公式仍保留在文档中。

### 12.3 可访问性与本地化

- 支持键盘完成所有核心操作。
- 支持高对比度、深色模式、100%–300% DPI 和多显示器。
- OMML 公式保留 Word 的数学辅助功能。
- SVG 回退提供可选的 MathML 或可读替代文本。
- 首发提供简体中文和英文界面。

## 13. 首发验收标准

### 13.1 安装与集成

- 在受支持的干净机器安装后，重新启动 Word 即可看到 FormulaBridge 功能区。
- 安装、升级和卸载不会破坏 Word 或已有公式。
- 64 位 Word 不加载任何 32 位进程内 FormulaBridge DLL。

### 13.2 编辑体验

- 三类公式均可通过功能区和快捷键插入。
- 任务窗格与浮动编辑器至少有一种达到正式发布质量，另一种可以在后续小版本交付。
- 选中或双击公式能够恢复源码、类型、样式和环境。
- 编译失败和取消操作不改变原文档。

### 13.3 TeX 与环境

- 能检测、添加、测试、选择和删除多个 TeX 环境配置。
- 能在文档级和公式级选择不同引擎。
- 宏包缺失时显示明确环境、宏包和解决建议。
- 本地 TeX 能输出自包含 SVG 和 PNG fallback。
- 默认安全配置下无法通过公式启动任意外部命令。

### 13.4 文档可移植性

- 未安装 FormulaBridge 的干净 Word 可以打开、显示、打印和导出全部公式。
- OMML 公式仍可使用 Word 原生工具编辑。
- 公式复制到另一文档后，LaTeX 源码和必要元数据随对象移动。
- 断开的引用、重复 UUID 和标签冲突可被检测并修复。

### 13.5 质量

- 所有自动化测试、Word 集成测试、安装测试和安全测试通过。
- 覆盖 Microsoft 365 Word 和 Office 2024 的正式兼容矩阵。
- 发布包完成数字签名、SBOM、第三方许可证和隐私检查。

## 15. 主要风险与处理策略

| 风险 | 影响 | 处理策略 |
| --- | --- | --- |
| VSTO 安装与运行时依赖较多 | 安装失败会导致功能区不出现 | 使用签名 MSI、先决条件检测、修复入口和干净虚拟机测试 |
| OMML 与完整 LaTeX 表达能力不同 | 转换结果可能降级 | 语义校验，无法可靠转换时使用 SVG 回退 |
| 多 TeX 环境结果不一致 | 同一源码在不同机器排版不同 | 保存环境能力要求，显式映射，不静默切换 |
| TeX 输入可触发危险操作 | 本地文件和系统安全风险 | 禁用 shell escape、隔离目录、超时、允许列表和进程限制 |
| 旧 Aurora 对象格式未完全掌握 | 迁移可能无法恢复源码 | 先建立真实语料，非破坏性迁移，无法恢复时保留原对象 |
| 文档级源码记录不能随单个公式复制 | 跨文档编辑体验丢失 | 增加对象级可移植元数据和冲突处理 |
| VSTO 受限于 .NET Framework | 长期维护成本 | VSTO 保持薄层，核心与 RenderHost 使用现代独立进程 |

## 16. 已验证的技术事实

- 已检查的 Aurora 安装实际为 2.2，核心程序和 Office 插件均为 32 位原生组件。
- 旧公式对象通过 `Equation.Ribbit` OLE ProgID 注册，Office 插件通过 `Aurora.Connect` 注册。
- 原版调用 `latex`、`pdflatex` 和 `dvipng`，并使用 `preview`、`anyfontsize`、`amsmath` 和 `amssymb`。
- 当前开发机的 TeX Live 2024 已成功完成 LaTeX → DVI、DVI → PNG、DVI → SVG 和 pdfLaTeX → PDF 烟雾测试。
- 已确认采用 VSTO + WebView2 + 独立 RenderHost 的 Windows 首发架构，并从干净代码基线实施。

这些事实证明总体方案可行，但旧公式源码的无损提取仍需要真实 Aurora 文档样本验证。
