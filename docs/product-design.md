## 1. 产品定义

FormulaBridge 是面向现代 Microsoft Word 的本地优先 LaTeX 公式编辑器。它继承 Aurora 用户熟悉的源码输入、编译预览、三类公式、快捷编辑和多 TeX 环境工作方式，但采用独立品牌、独立实现、现代 Word 数据模型和受限的本地渲染架构。

FormulaBridge 的核心承诺是：

- 用户能够继续用 LaTeX 高效输入公式，并在 Word 内获得可视化预览和编辑体验。
- 常见且能无损表达的公式保存为 Word 原生 OMML。
- 复杂宏包、自定义命令和特殊排版由用户已有的本地 TeX 生成高保真结果。
- 文档离开本机或卸载 FormulaBridge 后，公式仍能显示、打印和导出。
- LaTeX 源码随文档保存并能随普通 Word 复制粘贴移动。
- 打开文档不会自动执行其中的 TeX，也不会因为环境变化静默改变公式。

FormulaBridge 是闭源桌面产品，通过官方渠道提供签名安装包。1.0 可以预留商业授权边界，但账号、联网激活和商业许可证系统不构成发布门槛。

## 2. 产品目标与非目标

### 2.1 FormulaBridge 1.0 的目标

1. 在受支持的 Word 中提供可正式使用的公式插入、编辑和恢复闭环。
2. 支持行内、独立和编号公式，以及同文档连续编号与交叉引用。
3. 同时提供无损 OMML 路径和受隔离的本地 TeX 路径。
4. 允许用户检测、添加、验证和选择多个 TeX 安装及渲染配置。
5. 保障保存、重开、普通复制、打印、PDF 导出和卸载后的可见性。
6. 对公式源码、文档写入、安装更新和本地进程调用建立明确的信任边界。
7. 提供简体中文和英文界面，以及核心键盘和辅助技术支持。

### 2.2 FormulaBridge 1.0 的非目标

- 不支持 macOS、Word 网页版、PowerPoint、Excel 或 Visio。
- 不正式支持 32 位 Word、Windows ARM64、Windows 10、Word 2021 及更旧版本。
- 不把 `.dotx`、`.dotm`、`.doc`、`.rtf` 或 `.odt` 作为可管理文档格式。
- 不提供浮动编辑器和章节感知编号；二者进入 1.1。
- 不提供 Aurora 自动迁移；迁移助手属于后续 1.x。
- 不提供完整 OMML、MathML 或 PDF 片段导入导出。
- 不自动安装 TeX、宏包、字体或修改系统 `PATH`。
- 不开放 shell escape、任意文件读取、网络访问或云端渲染。
- 不实现实时多人公式元数据合并。

## 3. 设计原则

1. **LaTeX 权威**：保存的 LaTeX 是公式唯一的权威语义来源；OMML、SVG 和 PNG 是派生表示。
2. **OMML 只做无损转换**：只有 Core 能证明语义无损时才写入 OMML，不以“看起来相似”代替数学等价。
3. **TeX 保真回退**：超出 OMML 能力的公式由本地 TeX 渲染，并共同嵌入清理后的自包含 SVG 和 PNG fallback。
4. **文档自包含**：源码、可见结果、编号和必要元数据随 Word 文档保存，不依赖外部图片路径。
5. **失败不改文档**：编译、解析、迁移或写入失败时保留原公式，不留下半完成写入。
6. **显式执行**：打开或选中公式不会触发编译；编辑当前公式或确认批量范围才构成明确编译操作。
7. **显式环境**：文档声明能力要求，用户把要求映射到本机渲染配置；不静默换引擎或程序。
8. **本地隔离**：TeX 在 Word 进程外运行，受到身份、文件、网络、资源和输出限制。
9. **Word 原生协作**：在可靠的范围内使用 Word 内容控件、OMML、字段、书签和撤销机制。
10. **独立实现**：不复制或分发 Aurora 的代码、二进制、图标、帮助、激活机制和安装资源。

## 4. 目标用户与使用场景

### 4.1 首要用户

FormulaBridge 1.0 的首要用户是已经安装 TeX、使用现代 Windows Word 撰写论文或技术文档的个人科研用户，例如高校师生、科研人员和工程技术作者。

企业管理员、实时协作团队和 Aurora 迁移用户是后续服务对象，不作为 1.0 首发范围的主要驱动力。

### 4.2 核心场景

- 在光标处插入行内、独立或编号公式。
- 选中公式后点击“编辑”或使用快捷键恢复 LaTeX 源码。
- 在任务窗格中输入 LaTeX，并查看快速 OMML 预览或受限 TeX 预览。
- 使用 `amsmath`、`mathtools`、`physics`、`siunitx`、`mhchem` 等本机已安装宏包。
- 为不同项目选择不同年份的 TeX Live、MiKTeX 或自定义工具链。
- 给编号公式指定稳定标签，并插入可更新的 Word 原生引用。
- 普通复制公式到同一文档或另一文档，并继续恢复源码编辑。
- 批量检查或更新所选范围、当前文档的公式。
- 在未安装 FormulaBridge 的 Word 中继续查看、打印和导出公式。

## 5. 首发支持范围

### 5.1 平台与文档

- Windows 11 x64。
- Microsoft 365 Word x64：Current Channel 和 Monthly Enterprise Channel 的当前受支持版本。
- Office 2024 Word x64。
- `.docx` 和 `.docm`。
- 当前及前两个年度版 TeX Live、当前稳定 MiKTeX。
- 更旧 TeX 发行版、便携环境和自定义工具链可以添加，但属于尽力兼容。

`.docm` 中既有 VBA 项目对 FormulaBridge 完全不透明：产品不读取、不执行、不修改 VBA，并通过保存重开测试验证其保持性。

### 5.2 1.0 功能范围

- 签名的当前用户安装和 Word 功能区自动注册。
- Word 右侧停靠任务窗格。
- 行内、独立、编号三类公式。
- 插入、选中编辑、快捷键编辑和上一个/下一个公式导航。
- 自动、Word 原生、本地 TeX 三种渲染选择。
- 四种本地引擎路径：`latex`、`pdflatex`、`xelatex`、`lualatex`。
- 多 TeX 安装、多渲染配置、文档要求和公式覆盖配置。
- 固定顺序 preamble 组合、宏包诊断和自定义命令。
- 文档内连续编号、稳定标签、同文档 Word 原生引用。
- 普通复制粘贴的源码可移植性。
- LaTeX 文本复制/粘贴，以及当前公式的 LaTeX、SVG、PNG 导出。
- 轻量本地公式片段库。
- 文档和环境诊断、修复入口、脱敏日志与用户授权诊断包。
- 简体中文、英文、核心键盘操作、高对比度、屏幕阅读器标签和 100%–300% DPI。

## 6. 产品界面与信息架构

### 6.1 安装后在 Word 中出现的位置

签名安装包为当前用户注册 FormulaBridge VSTO 加载项。用户重新启动 Word 后，应当自动看到：

- “插入”选项卡中的 FormulaBridge 紧凑分组。
- 独立的“FormulaBridge”功能区选项卡。

主要命令包括：

- 行内公式、独立公式、编号公式。
- 编辑当前公式、上一个公式、下一个公式。
- 插入引用、更新受影响编号、更新全文。
- 从 LaTeX 粘贴、复制 LaTeX、导出当前公式。
- 批量更新、检查并修复。
- TeX 配置、文档设置和 FormulaBridge 诊断。

如果 Word 禁用加载项、组策略阻止加载或运行时缺失，安装包同时提供 Word 外部的“FormulaBridge 诊断与修复”入口。它检查注册、Office 位数、签名、VSTO/WebView2 运行时和禁用状态，但不绕过组织策略。

### 6.2 公式编辑界面

FormulaBridge 1.0 使用每个 Word 文档窗口独立的右侧停靠任务窗格。任务窗格包含：

- LaTeX 源码编辑区：行号、语法高亮、括号匹配、光标位置和常用补全。
- 可视化预览区：OMML 快速预览或受限本地 TeX 预览。
- 公式类型、渲染方式、渲染配置和状态提示。
- 简化错误、完整脱敏 TeX 日志和源码定位。
- 公式属性、文档 preamble、宏包和渲染配置入口。
- “预览”“插入/更新”“取消”和“恢复原内容”操作。

选择公式后点击“编辑”或使用快捷键必须可靠工作，是 1.0 发布要求。双击编辑属于尽力增强，不阻塞发布。浮动编辑窗口在 1.1 提供。

### 6.3 插入与编辑流程

插入公式：

1. 用户选择三种公式类型之一。
2. 任务窗格继承当前 Word 字号、颜色和段落上下文。
3. 用户输入 LaTeX；开始修改即允许对当前公式进行受限实时编译。
4. FormulaBridge 根据能力分析选择 OMML 或本地 TeX，用户也可强制本地 TeX。
5. 用户确认后，源码、可见表示和元数据作为一个 Word 撤销记录原子写入。

编辑公式：

1. FormulaBridge 读取公式身份、LaTeX、类型、样式和环境要求。
2. 用户修改并成功预览。
3. 确认更新后原位替换；失败或取消时原公式保持不变。

新建但尚未保存的 Word 文档也可以插入公式。元数据先进入内存文档包，受保护草稿为尚未提交的源码兜底；首次保存必须使用 `.docx` 或 `.docm`。

## 7. 核心功能设计

### 7.1 公式类型与样式

- **行内公式**：与正文同行，保持合理基线和行距。
- **独立公式**：单独成段并按文档段落规则布局。
- **编号公式**：公式与连续编号组合，并可由标签引用。

三种类型可以转换。转换保持 UUID、LaTeX、标签和受管理引用，并作为一次可撤销操作完成。

FormulaBridge 继承当前 Word 字号、颜色和段落位置。OMML 使用 Word 数学字体；本地 TeX 字体由渲染配置决定，不承诺两条路径逐像素相同。跨文档粘贴默认保留公式字号、颜色和显示方式，段落布局采用目标文档规则，并提供“匹配目标样式”。

### 7.2 双渲染策略

自动模式先由 Core 判断是否存在经过版本化验证的无损 OMML 转换：

```text
可证明无损：LaTeX -> AST -> OMML
其他情况：  LaTeX -> 本地 TeX -> 自包含 SVG + PNG fallback
```

自动模式不能因为 TeX 不可用而生成语义不完整的 OMML。用户可以强制本地 TeX；强制 Word 原生时，如果 Core 无法证明无损，必须阻止提交并说明不支持的构造。

本地 TeX 结果必须共同嵌入经过清理的 SVG 和 PNG fallback，并通过保存、重开、普通复制、打印和 PDF 导出验证。字体在许可和工具能力允许时转换为 SVG 路径，否则依靠 PNG fallback，并提示环境差异。

### 7.3 LaTeX、宏包与 preamble

1.0 支持常见数学命令、环境、自定义宏和本机已安装宏包。preamble 仅有三个组合层，固定顺序为：

1. 渲染配置 preamble。
2. 当前文档 preamble。
3. 当前公式附加项。

重复宏包选项或命令定义冲突属于错误，不进行隐式覆盖；需要替换定义时必须显式使用相应命令。缺失宏包诊断应指出宏包、所选 TeX 安装及 TeX Live/MiKTeX 的处理指引，但 1.0 不自动调用包管理器。

### 7.4 多 TeX 安装与渲染配置

产品区分以下概念：

- **TeX 安装**：本机实际存在的一套 TeX Live、MiKTeX 或便携发行版。
- **渲染配置**：一个 TeX 安装、一个引擎、转换器、preamble 和安全策略的组合。
- **文档环境要求**：文档保存的引擎、宏包、字体、能力和可选版本指纹，不含绝对路径。
- **公式覆盖配置**：单个公式对文档默认配置的明确覆盖。

用户可以设置全局默认、文档默认和公式覆盖配置。执行优先级为公式覆盖、文档映射、用户全局默认；任何改变都需要明确确认，不得静默切换引擎。

自动发现只生成候选项。自定义引擎和转换器必须由用户选择绝对路径，并通过版本检查和最小渲染测试；文件身份改变后批准失效。FormulaBridge 不依赖或修改系统 `PATH`，文档也不能指定可执行文件。

没有本地 TeX 时，OMML 插入和编辑仍然可用；TeX 公式的已有嵌入结果及源码仍可查看，但不能重新编译或覆盖。

### 7.5 编号与引用

FormulaBridge 1.0 使用 Word 原生 `SEQ`、`REF` 字段和书签实现连续编号与受管理引用：

- 每个编号公式可以拥有文档内唯一标签，例如 `eq:maxwell`。
- 重复标签在提交前被阻止，并可跳转到冲突公式。
- 标签重命名原子更新所有受管理引用。
- 插入、移动或删除时在同一撤销操作中更新受影响范围。
- 全文编号和字段更新由用户明确触发。
- 用户直接删除书签或字段产生断开引用，诊断负责报告，不猜测目标。

按 Word 标题生成章节号属于 1.1。

### 7.6 普通复制与身份

普通 Word `Ctrl+C/V` 必须保留 LaTeX 和必要元数据：

- 移动公式保持 UUID 和标签。
- 粘贴副本获得新 UUID，并默认清除标签。
- 现有引用继续指向原公式。
- 普通复制是 1.0 发布门槛，专用复制命令不能替代。

文档级权威源码以明文 Custom XML 保存。对象级复制载体必须通过受支持 Word 矩阵实测；如果 Custom XML 不能稳定随对象迁移，应使用其他可复制 OOXML 载体或组合载体，而不是降低产品要求。

### 7.7 分歧、损坏与修复

用户绕过 FormulaBridge 修改 OMML 时，公式被标记为“分歧公式”。用户可以：

- 用权威 LaTeX 恢复可见表示。
- 脱离 FormulaBridge，保留为普通 Word 公式。
- 仅在 Core 能证明无损时，预览差异并把 OMML 导入为新的 LaTeX 权威源码。

不支持的 OMML、SVG 和 PNG 不进行猜测、反向识别或 OCR。

可见内容存在但元数据损坏时，公式标记为“已脱离管理”，并提供重新录入、恢复或关联。重复 UUID、孤立元数据和损坏记录在打开文档时只报告；只有用户执行可撤销的“检查并修复”或确认保存清理时才修改。

### 7.8 批量操作与片段

批量更新采用两阶段流程：先验证和渲染，再写入 Word。出现失败时，用户可以全部取消，或明确选择将成功项按可审计、可撤销的分组应用；不得静默跳过失败项。

1.0 支持轻量本地公式片段，记录名称、LaTeX 和可选说明，不提供账号、云同步、团队共享或数据库式模板管理。

## 8. 文档生命周期与写入规则

### 8.1 可写状态

FormulaBridge 只在受支持文档处于普通可编辑状态时写入。以下状态允许查看公式和源码，但阻止插入、更新、删除、修复和重新编号：

- Word 修订模式。
- 实时共同编辑。
- 只读或受保护视图。
- 具有数字签名的文档。
- 不支持的文件格式。

不支持的格式应引导用户另存为新的 `.docx` 或 `.docm` 副本。FormulaBridge 不绕过文档保护；对数字签名文档必须说明任何写入都会使签名失效。

普通 OneDrive/SharePoint 同步和 AutoSave 可以使用，但 1.0 不合并多人同时修改的公式元数据。

### 8.2 会话、撤销与失败

- 每个 Word 文档窗口拥有独立任务窗格会话和文档配置。
- 同一文档的写入串行执行；本地渲染使用有上限的跨文档队列。
- 插入、更新、类型转换和编号操作各自形成可理解的 Word 撤销记录。
- 批量写入采用明确分组；取消不得留下半完成公式。
- 写入后验证可见对象与元数据关系；验证失败立即回滚。

### 8.3 元数据版本

旧版 FormulaBridge 遇到更高架构版本时，只显示可见表示并在安全范围内只读源码，不降级覆盖。新版读取旧架构时先只读验证；用户首次确认写入时才迁移，并保留旧记录直到成功保存和重开验证。重大迁移提示另存副本。

文档内 LaTeX 是明文 Custom XML，其保密性继承 Word 文档自身的加密和访问控制。产品必须明确说明：能解包未加密 DOCX 的人也能读取其中源码。

## 9. 本地数据、诊断与隐私

### 9.1 本地数据

- 渲染缓存只保存清理后的 SVG/PNG、尺寸和不可逆哈希，不保存明文源码或完整日志。
- 未提交编辑草稿使用当前 Windows 用户保护机制加密，与缓存分离。
- 默认保留：渲染缓存 1 GiB/30 天 LRU、脱敏日志 20 MiB/14 天、加密草稿 7 天。
- 用户可以缩短保留期、禁用或立即清除。

### 9.2 日志与诊断包

编辑器可以显示该次作业的完整脱敏日志。原始日志只在用户明确授权时临时导出，并提示可能含有源码、用户名或路径。

默认诊断包不包含公式源码、文档内容、文件名和用户路径。源码、文档片段和原始日志必须逐项授权并在发送前预览。FormulaBridge 不自动上传诊断包。

### 9.3 联网行为

- 公式、文档和编译日志默认不离开本机。
- 遥测默认关闭。
- 1.0 不实现云端渲染或云同步。
- 联网更新检查默认关闭；用户可以立即检查或主动启用周期检查。

## 10. 安装、更新与卸载体验

### 10.1 安装

- 提供闭源、签名、当前用户安装包。
- 安装 FormulaBridge WordAddIn、RenderHost、本地 WebView2 资源、外部诊断工具和卸载器。
- 注册 Word 自动加载；安装完成后提示重新启动 Word。
- 不捆绑或自动下载 TeX。
- 不静默提权。
- 缺少 VSTO 或 WebView2 运行时时，提供独立签名的先决条件安装入口；编辑保持禁用并给出明确说明。

企业机器级安装、静默集中部署和 32 位安装包不属于 1.0 首发渠道。

### 10.2 更新

- 稳定通道为默认；预览通道需要用户明确加入并显示风险。
- 清单和安装包必须验证签名、哈希、版本和防降级规则。
- 更新等待所有 Word 实例和 RenderHost 退出后安装。
- WordAddIn、RenderHost 和前端资源作为兼容集合整体升级或回滚。
- 安装始终需要用户确认，不进行静默更新。

### 10.3 卸载

卸载绝不修改用户文档。卸载器删除程序、缓存和普通日志，并允许用户选择是否保留设置、渲染配置和受保护草稿。已插入公式在没有 FormulaBridge 时仍应可见、可打印和可导出。

## 11. 安全要求

### 11.1 文档 TeX 信任边界

从 Word 文档读取的源码和 preamble 一律不可信：

- 打开或选择公式不触发编译。
- 默认强制 `-no-shell-escape`。
- 公式不能读取任意文档目录或用户路径，也不能访问网络。
- 单次作业只允许读取已批准 TeX 安装和随机任务目录。
- 每次作业使用受限子进程身份、Windows Job Object、文件 ACL、TeX 输入输出策略和网络阻断。

初始不可由文档放宽的资源上限：

- 输入 256 KiB。
- 交互编译 30 秒。
- 批量单项 120 秒。
- 内存 1 GiB。
- 最多 64 个输出文件，合计不超过 64 MiB。

这些数值可以由后续产品版本依据发布语料调整，但用户文档不能提高权限或上限。

### 11.2 本地调用与内容安全

- WebView2 只与 WordAddIn 通信。
- WordAddIn 通过当前用户 Named Pipe、每次启动随机能力令牌和协议握手调用 RenderHost。
- 能力令牌不进入文档、设置或日志。
- 正式产品不开放本地 HTTP 编译接口。
- SVG 必须移除脚本、事件处理器、外部 URL 和非预期资源。

## 12. 非功能要求

### 12.1 性能预算

在约定参考机器和发布语料上：

- Word 功能区加载 p95 不超过 2 秒。
- 任务窗格热启动不超过 1 秒。
- 常见 OMML 预览 p95 不超过 100 毫秒。
- 常见未缓存 TeX 预览 p95 不超过 2 秒。
- 1000 公式文档索引不超过 3 秒，且不自动编译。

### 12.2 稳定性与可恢复性

- RenderHost 崩溃不得导致 Word 退出。
- 可见内容与元数据必须原子提交。
- 环境变化只把公式标记为“待更新”，不自动覆盖嵌入结果。
- Word 或编辑器异常退出后，可见公式仍保留，未提交源码可从受保护草稿恢复。
- 缓存和日志损坏不得影响文档可见内容。

### 12.3 可访问性与本地化

- 核心流程可完全通过键盘完成。
- 支持高对比度、屏幕阅读器标签和 100%–300% DPI。
- OMML 保留 Word 数学辅助能力。
- TeX 图片公式由 AST 生成清理后的可读文本或 MathML 语义；无法可靠生成时明确提示并允许用户编辑说明。
- 首发提供简体中文和英文。

## 13. 首发验收标准

### 13.1 前置可行性门槛

完整功能开发前必须在受支持 Word 矩阵上通过四个可执行样机：

1. 签名的用户级 VSTO 安装、Word 重启后自动出现功能区。
2. 普通 `Ctrl+C/V` 跨文档携带源码和必要元数据。
3. SVG+PNG 经过保存、重开、复制、打印和 PDF 导出仍正确。
4. 恶意 TeX 无法读取受控根之外文件或绕过进程与网络限制。

失败时必须修改相应架构决策并重新验证，不能把风险推迟到发布测试。

### 13.2 功能验收

- 三类公式可以通过功能区和快捷键插入、编辑、取消和撤销。
- 任务窗格达到正式发布质量；双击不是发布门槛。
- 自动渲染不会生成语义不完整的 OMML。
- 四种首发引擎路径和多配置选择通过测试。
- 缺少 TeX、宏包、字体或映射时有明确且非破坏性的降级行为。
- 连续编号、标签、引用、标签重命名和断开引用诊断正确。
- 普通复制产生新身份并清除标签，移动保留身份。
- 未安装 FormulaBridge 的干净 Word 可以打开、显示、打印和导出全部公式。

### 13.3 文档与安全验收

- `.docx`、`.docm` 保存和重开保持源码、可见结果、VBA 与关系结构。
- 修订、共同编辑、保护、签名和不支持格式状态不发生越权写入。
- 元数据损坏、重复 UUID、孤立记录和新旧架构冲突不会静默改文档。
- 所有写入可撤销，失败与取消不留下部分状态。
- 默认设置下不能执行任意外部程序、读取任意用户文件或访问网络。
- 更新和安装产物通过完整签名与防降级验证。

### 13.4 不可豁免发布阻断项

出现以下任意已知问题，FormulaBridge 1.0 不得正式发布：

- 文档损坏或数据丢失。
- 静默数学语义变化。
- TeX 隔离逃逸或未授权代码执行。
- FormulaBridge 导致 Word 崩溃。
- 签名、更新验证或权限边界被绕过。
- 任一前置样机或受支持发布矩阵未通过。

## 14. 版本路线

### 阶段 0：高风险样机

- VSTO 用户级安装与自动加载。
- 普通复制元数据载体。
- SVG+PNG Word 往返。
- TeX 文件系统隔离。

### 阶段 1：纵向产品闭环

完成“安装 → 功能区 → 任务窗格 → 编辑 → OMML/TeX → 原子写入 → 保存重开 → 恢复编辑”的生产形态闭环。

### 阶段 2：FormulaBridge 1.0

在纵向闭环上补齐三类公式、四引擎、多配置、宏包诊断、普通复制、基本编号与引用、批量更新、片段、诊断、安全、安装更新和完整发布矩阵。

### 阶段 3：FormulaBridge 1.1

- 可分离的浮动编辑器。
- 章节感知编号与更丰富的编号格式。

### 阶段 4：后续 1.x

- Aurora 迁移助手：用户显式启动、独立实现、使用公开格式知识、不注册或冒用 `Equation.Ribbit` 的 CLSID、ProgID 或品牌，始终输出新文档和迁移审计报告，不覆盖原文件。
- 更完整的 OMML、MathML、PDF 片段导入导出。
- 经过显式资源导入的受控 TeX 外部文件支持。
- 企业机器级部署与集中管理。

32 位 Word、ARM64、Office.js、macOS 和 Word 网页版只有在 Windows 1.x 核心产品稳定后才重新评估。

## 15. 发布验证语料

每次发布必须使用版本化、无隐私数据并可重复运行的公式与 Word 文档语料，至少覆盖：

- 常见数学结构和 OMML 无损边界。
- `latex`、`pdflatex`、`xelatex`、`lualatex`。
- 专业宏包、自定义命令、中文和特殊字体。
- SVG 辅助说明与键盘流程。
- 普通复制、保存重开、打印和 PDF 导出。
- 1、100 和 1000 个公式的文档。
- 缺失环境、损坏元数据、重复身份和批量失败。
- 路径读取、网络、资源耗尽和进程逃逸等恶意 TeX。

发布报告必须记录 Word、Windows、TeX、FormulaBridge 版本及结果，不能只依赖临时人工公式或真实用户私有文档。
